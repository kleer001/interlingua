# Semantic Phonology

A plan for replacing the hash-based stem assignment in Stage 6 with the
natural-neighbor interpolation that `anchor-pool-sketch.md` originally
called for. This is the *pure expensive pass* — we throw away the
hash-derived lexicon and regenerate every stem from the SAE substrate,
grounded in the anchor pool. The cost is real and documented below.

**Companion docs:** `anchor-pool-sketch.md` (the design this implements),
`docs/grammar.md` §"Phonosemantic stems" (the hash scheme being
replaced), `spec.md` v0.2 (the pipeline this sits inside),
`POST-GLUE-SKETCH.md` (separate research thread, not this one).

---

## 1. The bad choice and the penalty

`docs/grammar.md` currently documents stems as `CV1 + CV2 + CV3` where:

- `CV1` = hash of the HDBSCAN cluster ID
- `CV2` = hash of the highest-PMI parent's feature ID
- `CV3` = hash of the feature's own ID
- `CV4+` = salted hash for collision resolution

This was a stopgap: it satisfied the *structural* commitment from
spec.md (siblings share a syllable, parent-relatives share a syllable)
with one line of Python per syllable. It was supposed to be the
placeholder while the real design — Sibson natural-neighbor
interpolation across anchor signatures in semantic space — got built.
The placeholder shipped. The real design didn't. This document is
where we admit that and stage the unwinding.

**Why hash was the wrong function.** Hash is uniformly distributed. It
preserves discrete relationships ("same cluster: yes / no") and
destroys continuous ones ("how close, in what direction"). Two features
0.01 apart in SAE cosine and two features 10.0 apart get equally
unrelated `CV1` prefixes. The first-class philosophy of this project
is fidelity to the hidden language between languages; hash is
deliberate scrambling of exactly the geometry that fidelity is owed to.

**The penalty.** When this lands:

- Every stem in `docs/static/lexicon.html` is regenerated. `wadigase`
  for "social justice" goes away; a new stem assigned by interpolation
  takes its place. The fossil should be committed for diff comparison
  but not preserved as canonical.
- The 1000-entry lexicon snapshot becomes substrate-dependent rather
  than ID-dependent. Future regeneration requires the SAE substrate
  vectors to be archived, not just the feature IDs.
- Reproducibility breaks across the cutover: hash-based stems were
  deterministic from feature IDs alone; interpolation-based stems
  depend on the substrate snapshot, the anchor pool snapshot, and the
  interpolation tuning parameters.
- Class prefixes, sandhi, negation, phonotactics, word-minimum — all
  unchanged. Phonology inventory (16C + 5V + digraphs) unchanged;
  `r` was added in the previous commit specifically to widen the
  expressive range this pass needs.

We pay because the hash version cannot answer the question this
project exists to answer: *does the phonology of a stem carry meaning
from the model's interlingua, or is it noise stapled onto an ID?*
Right now it's noise. After this pass, it carries meaning by
construction.

## 2. What the design always called for

From `anchor-pool-sketch.md` §"The premise":

> Phonology is generated by Sibson natural-neighbor interpolation in
> semantic space, with anchors drawn from cross-linguistic
> onomatopoeia. … An incoming LLM-extracted concept embeds somewhere
> in semantic space, lands among the surrounding attribute points,
> and receives phonology by interpolation across whichever anchors
> are its natural neighbors.

Restated as an objective:

> Define φ: feature → stem such that if features fᵢ and fⱼ are close
> in SAE substrate space, then stems φ(fᵢ) and φ(fⱼ) are close in
> phonological space, where phonological distance is the same
> panphon-feature Euclidean metric `project_ipa()` already uses for
> the anchor projection.

This is lossy by construction. SAE substrate is high-dimensional;
phonological space is small (16C × 5V × ≈3 syllables ≈ 2.5M legal
stems before phonotactic filtering). The goal is approximate metric
preservation, not bijection. The lossy compression is what carries
meaning — features cluster in semantic space, and clustering survives
the projection as phonological resemblance.

## 3. Phased plan

Staged so we can stop, evaluate, and ship at each cut.

### Phase 0 — Freeze the substrate, pick N

Pre-work. No user-visible change.

- **Set N = 2000 for v1.** The current pipeline took the first 1000
  filter-passing features (via `slice.py --top-n 1000`). Bumping to
  2000 is a one-line CLI change and nearly doubles vocabulary coverage
  at near-zero compute cost — the dominant cost in the pipeline is the
  co-activation forward pass over FLORES, which is bounded by corpus
  size, not N. See §"N is a knob, not a constant" below for the
  upper-bound conditions and the curve.
- Snapshot SAE feature vectors and the HDBSCAN cluster outputs into
  `data/processed/substrate-v1.parquet`. Every later phase reads from
  this; nothing reads from a live extraction. Filename embeds N
  (`substrate-v1-n2000.parquet`) so a future scale-up doesn't silently
  clobber.
- Snapshot the anchor pool's per-concept modal projections and
  feature-space embeddings into `data/processed/anchors-v1.parquet`.
- Tag the current `docs/static/lexicon.html` as `lexicon-pre-cutover`
  and commit it as the fossil. The cutover commit will overwrite it.
- Add `phonological_distance(stem_a, stem_b) -> float` next to
  `project_ipa()`. Panphon-feature Euclidean over aligned segments.
  This is the metric every later phase tunes against; we cannot
  validate without it.

Acceptance: substrate + anchors parquet files exist, `phonological_distance`
has tests, fossil lexicon committed, N=2000 chosen and recorded in the
substrate filename and in `grammar.md` §"Phonosemantic stems".

### N is a knob, not a constant

The bottleneck is the co-activation forward pass over the corpus, and
that's roughly flat in N. Almost everything else (ingest, HDBSCAN, PMI
matrix construction, interpolation, validation) is either O(N) or
O(N²) on small constants. Wall-clock cost from 1k → 10k changes by
minutes, not hours. The real cost curve is in *lexicon utility*, not
compute, and it has four knees:

- **1k → 2k:** nearly free, doubles coverage. The v1 target.
- **2k → 5k:** auto-interp explanation quality starts to fray in the
  tail (lower-confidence Neuronpedia labels). Phonotactic pressure
  rises: 16C × 5V = 80 distinct CVs, so unique 2-syllable openings cap
  at 6400. Anchor density per feature drops below 1 anchor per 20
  features. Conditional on growing `concepts.py` from ~100 to ~150
  anchors before the bump.
- **5k → 10k:** same compute, but the cracks widen. Average stem length
  has to go from 3 syllables to 4 to avoid collisions. Most features
  get *relational* stems (located via natural-neighbor mixing among
  other unanchored features) rather than *iconically grounded* ones
  (located near actual onomatopoeia anchors). This defeats the point
  of the pure expensive pass.
- **> 10k:** requires switching the SAE itself from `width_16k` to
  `width_32k` / `width_65k`. Out of scope for this cutover.

**Floor on anchor density.** Empirical rule from the four knees above:
keep ≥ 1 anchor per 20 features, i.e. `len(concepts.py) ≥ N / 20`.
With ~100 anchors today, the comfortable ceiling is N ≈ 2000. The 5k
and 10k tiers are gated on growing the anchor pool first, in that
order. Don't bump N past 2000 until `concepts.py` grows.

The interpolation code in Phase 1 should be N-agnostic — passing
substrate parquet in, getting stems out, with no hardcoded 1000 or
2000 anywhere.

### Phase 1 — Interpolation infrastructure

Build the natural-neighbor lookup as a library module
(`src/conlang/interpolate.py`) without yet touching the lexicon
generator.

- Voronoi / natural-neighbor weights over anchor positions in SAE
  space. For an arbitrary query point (= an SAE feature vector),
  return the (anchor_slug, weight) list of its natural neighbors and
  their Sibson weights.
- Anchor-signature mixer: given those weighted anchors, blend their
  modal-projection forms into a target signature in the 16C/5V
  inventory. Mixing is per-segment-position over panphon feature
  vectors, weighted by Sibson weight; the result is a continuous
  feature target, not yet a discrete stem.
- Discretization: project the continuous feature target back to the
  nearest inventory phonemes. This reuses `project_segment()` from
  `anchors/project.py`, which already does feature-vector
  nearest-neighbor.
- Phonotactic gate: enforce (C)V syllables, ≥ 2 syllables, no illegal
  clusters. Where the discretization produces an illegal sequence,
  fall back to the second-nearest phoneme that keeps the syllable
  legal. Document fallback rate; if it's high, the inventory is
  underexpressive and we revisit §"Inventory candidates under review"
  in grammar.md.

Acceptance: given a feature vector and an anchor pool, the module
returns a stem. Round-trip tests: a feature placed exactly at an
anchor's position should produce a stem within edit-distance ≤ 1 of
that anchor's modal projection.

### Phase 2 — Cutover

Replace `build_stem()` in `src/conlang/lexicon.py` with the
interpolation path. Regenerate the 1000-entry lexicon.

- The composition order `[negation?] + [class] + [stem]` does not
  change.
- Class assignment per feature does not change — the same
  feature-to-class rule from current Stage 6 applies. Only the stem
  body is regenerated.
- Collision resolution: interpolated stems will collide more than
  hashed ones because nearby features get nearby stems by design.
  Resolution is no longer "append a salted CV4" (which would re-inject
  hash noise into a meaningful stem). Instead: extend the stem by one
  syllable derived from the *direction* between the colliding feature
  and its nearest neighbor in substrate space. Colliding features pull
  apart along the axis on which they actually differ.
- Update `grammar.md` §"Phonosemantic stems" to reflect the new
  scheme. The CV1/CV2/CV3 framing dies; the new framing is
  anchor-interpolated with a directionality-resolved tail.

Acceptance: lexicon rebuilds cleanly, all stems pass phonotactic
validation, collision rate ≤ 5% on the 1000-entry slice.

### Phase 3 — Validation

Acceptance is a metric, not a vibe.

- **Spearman ρ** between `cosine_distance(feature_i, feature_j)` and
  `phonological_distance(stem_i, stem_j)` on a random sample of
  ≥ 10,000 feature pairs. The hash baseline scores near 0 on this
  metric (which is the proof of §1). Phase 2 should score
  ρ ≥ 0.4. If it doesn't, the interpolation isn't working.
- **Anchor recall.** Features whose nearest semantic neighbor *is* an
  anchor should produce stems whose nearest phonological neighbor in
  the anchor pool is that same anchor. Target: ≥ 70% top-1 recall on
  held-out features.
- **Hand audit.** Pick 30 features by category (animals, abstracts,
  emotions, mechanical, spatial). For each, the stem should be
  defensible — either iconically grounded (animals, mechanical) or
  topologically grounded near plausible neighbors (abstracts). Binary
  pass/fail per stem; threshold 24/30.

If Phase 3 fails any threshold, the diagnostic is built in: low
Spearman → interpolation isn't preserving distance; low anchor recall
→ discretization is dominating; failed hand audit → the anchor pool
itself is too sparse and we need more concepts in `concepts.py`
before the cutover lands.

**Interpretation as of 2026-05-18.** All four measurements sit far
below the 0.15 cutover threshold and far below §5's 0.2 "consonant
directionality is real" threshold. The §5 "open questions" §
*Consonant directionality is the load-bearing claim* explicitly
anticipated this outcome: if ρ < 0.2, consonant features alone are
not enough.

The 1574-anchor attribute-level run is the critical negative:
**granularity per se is not the bottleneck.** Going from 63 to 1574
anchors (25×) *decreased* ρ. The only variable that changed was the
embed text — from iconic seed (`"hiss"`) to slug-prefixed abstract
attribute (`"snake_hissing :: evil-bringer-abrahamic"`). The iconic
phonological signal in the seed string was doing real work, and the
attribute regime traded it for slug+attribute abstraction. Whatever
modest correlation existed at 0.0365 likely *was* the seed's iconicity
leaking through Gemma's residual.

Next-rung experiments queued (per §5, not §3):
1. Reinstate the iconic seed inside the attribute embed text:
   `f"{slug} ({seed}) :: {attribute}"`. Tests whether seed-iconicity
   was the swing factor distinct from anchor granularity.
2. Layer-sweep at concept-level. Currently embedding from layer-13
   (output of block 12). Earlier layers carry more lexical/phonological
   info; later layers more abstract semantics. If no layer breaks
   ρ ≥ 0.10, the cutover hypothesis is empirically dead at 2304-d.

## 4. What stays the same

Stated explicitly because the surface area of "Stage 6" is large
enough that it's worth naming what does NOT move:

- The 16-consonant + 5-vowel inventory and the digraphs / prenasalized
  onsets in `docs/grammar.md` §"Phonology". `r` was added in
  preparation for this pass; no further inventory growth is part of
  the cutover.
- The 11 noun classes, class-9 sandhi, `si-` negation, (C)V
  phonotactics, ≥ 2-syllable word minimum.
- `src/conlang/anchors/` — the entire anchor-pool pipeline (Wikipedia
  + Wiktionary fetch, IPA parsing, 10C/5V projection, signature
  building). Its output is the *input* to Phase 1; nothing about how
  it's built changes.
- `src/conlang/phonology.py` — pure data + composition, no semantic
  logic. Stays as the morphology layer.
- Stages 1–4 of the spec — SAE feature extraction, clustering, graph
  regularization. The cutover is downstream of all of it.

## 5. Open questions

- **Substrate locking.** Stems become tied to a specific SAE
  checkpoint. Every re-extraction (new model, different probe set,
  bigger feature dictionary) regenerates the lexicon. Acceptable for
  a v1 artifact, but eventually we need a story for substrate
  versioning — `substrate-v1` → `substrate-v2` should preserve
  identity for features that survive, and the lexicon diff should be
  comprehensible. Out of scope for this pass; documented for the next.
- **Anchor sparsity for abstracts.** Concepts like JUSTICE, DEMOCRACY,
  HOPE have no plausible onomatopoeic anchor nearby. Sibson
  interpolation will still hand them a stem — the natural neighbors
  will be whatever animals/sounds happen to sit nearest in the SAE
  geometry — but the result is *relational*, not iconic. That's
  philosophically correct (it reveals how the model has bundled the
  abstract concept) but visually weird. Document this as a feature,
  not a bug. The "cunning → sibilant" walkthrough in
  `anchor-pool-sketch.md` already commits to this stance.
- **Anchor-density tradeoff.** This is the dual of anchor sparsity for
  abstracts, and the one that gates the N knob in Phase 0. With ~100
  anchors in `concepts.py` and N=2000 features, the ratio is 1 anchor
  per 20 features — enough for natural-neighbor interpolation to
  ground most stems in *some* iconic signal. As N grows the ratio
  collapses, and beyond ~1:20 most features end up being interpolated
  among other unanchored features (relational stems) rather than
  among anchors (iconic stems). The cutover loses its point when most
  stems are relational. Concrete consequence for the project plan:
  growing `concepts.py` is *prerequisite work* for scaling N past
  2000, not optional polish. Add ~50 anchors before pushing to 5k,
  ~200 more before 10k. Animal sounds are mostly tapped; the next
  tiers are weather, human-body sounds, mechanical/material sounds,
  and ideophones from ideophone-rich languages (Japanese, Korean,
  Bantu). `anchor-pool-sketch.md` §"Open questions" already flags
  non-animal anchors as the natural next expansion.
- **Mixing metric mismatch.** SAE cosine and panphon Euclidean are
  different metric kinds (angular vs L2). Sibson weights are
  scale-equivariant in the semantic space but the projection back to
  phonological space is not. Calibration is a tuning knob — start
  with uniform weighting, instrument the Phase-3 Spearman against
  reweighting, ship the empirical best.
- **Consonant directionality is the load-bearing claim.** This
  cutover is the experiment that tests it: does anchoring stems in
  consonant-feature space produce semantically coherent geometry, or
  does it just produce noise wearing a metric's clothes? If Phase 3
  Spearman ρ < 0.2, the answer is no and consonant features are not
  enough — we either expand the inventory further or accept that the
  phonology can only encode coarse structure.
- **Query interface.** This plan rebuilds the lexicon. It does NOT
  add the "give me the stem nearest to 'justice'" query layer that
  prompted the rewrite. That's a separate `src/conlang/semantic_neighbors.py`
  module consuming `substrate-v1.parquet`. Should land alongside
  Phase 1 (the interpolation library makes it a thin wrapper) but
  isn't on the critical path for cutover.

## 6. Order of work

1. Phase 0 (snapshot + fossilize + distance metric) — small, no risk,
   unblocks everything.
2. Phase 1 (interpolation library) — the real engineering. Build with
   tests; do not touch `lexicon.py` yet.
3. `semantic_neighbors.py` query wrapper — uses Phase 1 internals, no
   lexicon change. Lets us answer questions like "closest concept to
   'justice'" today, even before cutover.
4. Phase 2 (cutover) — single commit that regenerates the lexicon and
   updates `grammar.md`. Atomic.
5. Phase 3 (validation) — metrics committed as a script in
   `notebooks/` or `scripts/`, run on every regeneration.

Stop conditions: ship after Phase 1 if interpolation library is
enough and the lexicon can wait. Ship after Phase 2 if validation
metrics are clean enough on inspection that Phase 3 is bookkeeping.
Do not skip Phase 3 if Spearman ρ is unmeasured; that metric is the
whole point.
