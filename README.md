# interlingua

A bottom-up conlang whose lexicon is derived from the internal features of a
transformer (Gemma 2, 2B). Each word corresponds to a learned concept-detector
in the model's residual stream; relationships between words come from the
geometry of those detectors plus how they co-fire on real multilingual text.

The thesis: *the units of meaning a transformer has already learned* can be
surfaced as a vocabulary. The design constraints live in
[`spec.md`](spec.md) (v0.2) and [`prior-work.md`](prior-work.md) (v0.3).

> Not a language to speak. A tool to inspect a model's conceptual carving
> with the part of human cognition that handles words.

---

## Pipeline

Six stages. Stages 1–5 produce a structural graph; Stage 6 dresses it in
phonology.

```
┌──────────────────────────┐
│ 1. Ingest                │  SAE features + Neuronpedia descriptions
│ 2. Dedupe + cluster      │  cosine + HDBSCAN
│ 3. Edges                 │  cosine, co-activation (PMI), [crystals: failed]
│ 4. Decision gate         │  3-question check against spec §7
│ 5. Regularize            │  parent / siblings / near schema
│ 6. Phonology + site      │  two tracks (see below)
└──────────────────────────┘
```

Each stage is a small CLI in the `conlang` package and writes intermediate
artifacts under `data/` (which lives on a fast NVMe and is symlinked into
the repo).

### Setup

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

Heavy artifacts (SAE weights, Gemma 2 2B, the lexicon's interim NumPy
arrays) live on a separate disk; `data/` and `.venv` in this repo are
symlinks. See `CLAUDE.md` and `BREADCRUMB.md` for the local layout
conventions.

### Run

The full SAE pipeline (stages 1–5 plus the Bantu-track Stage 6):

```bash
source .venv/bin/activate
python -m conlang.slice \
    --sae-release gemma-scope-2b-pt-res-canonical \
    --sae-id layer_12/width_16k/canonical \
    --neuronpedia-model gemma-2-2b \
    --neuronpedia-source 12-gemmascope-res-16k \
    --top-n 1000 --dedup-method hdbscan
python -m conlang.run_coactivation --use-flores --n-per-lang 1000
python -m conlang.regularize
python -m conlang.lexicon
python -m conlang.site
```

The viz renders with cytoscape.js by default (`--viz-backend cytoscape`);
`--viz-backend pyvis` is kept as a fallback. Co-activation needs a GPU and
takes a few minutes; the rest of the stages finish in seconds.

### Test

```bash
pytest
```

## Stage 6: two parallel tracks

Stage 6 — assigning phonology to the 1000-node lexicon — is the place where
"a language" actually appears. The repo currently carries two distinct
approaches:

### Track A — `anchors/` (canonical, in progress)

Phonology generated by Sibson natural-neighbor interpolation in semantic
space, with anchors drawn from cross-linguistic onomatopoeia. Animal
sounds are universally recognized and onomatopoeic in nearly every
language, so each animal contributes (i) a cross-linguistic phonological
signature and (ii) a bundle of semantic attributes. An incoming
LLM-extracted concept lands among neighboring attribute points and
receives its phonology by interpolation.

- Sketch: [`anchor-pool-sketch.md`](anchor-pool-sketch.md)
- Data plan: [`anchor-data-plan.md`](anchor-data-plan.md)
- Code: `src/conlang/anchors/`
- Inventory: **10 consonants / 5 vowels + optional /n/ coda** (typological
  fit, every segment is in the vast majority of the world's languages).
- Current state: thousands of onomatopoeic words across 100+ languages
  across ~100+ canonical concepts, all projected to the 10C/5V inventory,
  with sharp-vs-fuzzy cross-linguistic anchors computed. See
  `src/conlang/anchors/showcase.py` and the latest
  `anchoring/processed/anchors-v*.jsonl` for current counts; the dataset
  grows as fetchers cover more languages and concepts.

### Track B — `phonology.py` + `lexicon.py` (deterministic baseline)

A Bantu-shaped phonology with a keyword class-assignment heuristic and
hash-based phonosemantic stems. Each stem's first syllable encodes its
HDBSCAN cluster (siblings audibly share the prefix); the second encodes
its highest-PMI co-activation parent (PMI-related nodes share the
prefix); the third is a per-node unique hash. Collisions get an
additional syllable.

- Code: `src/conlang/phonology.py`, `src/conlang/lexicon.py`
- Inventory: **15 consonants / 5 vowels** + 2 nasal digraphs + 4
  prenasalized onsets (Swahili-shaped).
- 11 noun classes, productive `si-` negation prefix (per spec §7
  Commitment 7: compositional negation, no `transformation` primitive).
- Class 9 has a two-allomorph rule (prenasalized stop for stops; `yi-`
  for everything else) because pure homorganic sandhi would produce
  illegal `ng+k` / `n+s` / `n+w` onsets.

Treat Track B as the simple null hypothesis. It's deterministic,
reproducible, and ships a complete 1000-entry lexicon today, so anchors
has a concrete thing to beat.

## Deliverables (Track B)

Three views of the Bantu-track lexicon, for three audiences:

| Deliverable                          | Path                                    | Audience          |
| ------------------------------------ | --------------------------------------- | ----------------- |
| Single-page lexicon (1000 rows, sortable + filterable) | `docs/static/lexicon.html` | demo / share      |
| Multi-page MkDocs site (origin + grammar + methodology + lexicon) | `docs-site/` (committed); also deployed via GitHub Pages | deep dive         |
| Executed walkthrough notebook        | `notebooks/walkthrough.ipynb`, HTML at `docs/static/walkthrough.html` | reproducibility   |

The MkDocs site source lives under `docs/`; the built output lives at
`docs-site/` and is committed so it can be browsed straight from the
repo. The site is also auto-deployed to GitHub Pages on every push that
touches `docs/` or `mkdocs.yml` — see
[`.github/workflows/deploy-pages.yml`](.github/workflows/deploy-pages.yml).
Enable Pages once at *Settings → Pages → Source: GitHub Actions* and
the deployed URL appears in the workflow run output.

To rebuild locally after changing anything in `docs/` or the lexicon:

```bash
python -m conlang.site                  # → docs/static/lexicon.html
mkdocs build                            # → docs-site/
python notebooks/build_walkthrough.py   # regenerate notebook source
jupyter nbconvert --to notebook --execute --inplace notebooks/walkthrough.ipynb
jupyter nbconvert --to html --output-dir docs/static notebooks/walkthrough.ipynb
```

## Supplementary: circuit-tracer attribution graphs

Three small attribution graphs from
[circuit-tracer](https://github.com/safety-research/circuit-tracer) ship
with the methodology page as illustrative material. They are *not*
integrated into the SAE-based lexicon graph — circuit-tracer operates on
MLP transcoders (`mntss/gemma-scope-transcoders`), a different feature
space than the residual-stream SAE that drives this work. Cross-space
alignment would need its own §7-style distinctiveness gate.

Driver: `external/run_circuit_tracer.py` (lives on the fauna disk;
requires `pip install -e ./external/circuit-tracer/` and downloads ~3 GB
of transcoder weights into the HF cache on first run).
