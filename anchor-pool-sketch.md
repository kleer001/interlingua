# Anchor Pool Sketch

A working sketch, not a spec. Companion to the phonology-generation-by-interpolation idea.

## The premise

Phonology is generated by Sibson natural-neighbor interpolation in semantic space, with anchors drawn from cross-linguistic onomatopoeia. **Animal sounds** are an ideal anchor type: universally recognized, cross-linguistically attested, attached to rich attribute clusters, and onomatopoeic in nearly every language.

Each animal contributes two things to the system:

1. A **cross-linguistic phonological signature** — the cloud of ways N languages represent its sound, normalized into our 10C/5V CV(n) inventory.
2. A **bundle of semantic attributes** — size, motion, environment, texture, temperament, cultural valence — each one a semantic dimension or embedding.

An incoming LLM-extracted concept embeds somewhere in semantic space, lands among the surrounding attribute points, and receives phonology by interpolation across whichever anchors are its natural neighbors.

## Structure

For each `(animal, language)` pair we have:

- Native-language onomatopoeia (e.g. English *moo*, Japanese *モーモー*, Spanish *muu*)
- IPA transcription (e.g. /muː/, /moːmoː/, /mu/)
- Phonological feature vector after projection onto our inventory

For each `animal` we have:

- A list of attributes — each represented as a semantic embedding in the same coordinate system as the LLM-extracted features
- A cross-linguistic phonological signature derived from aggregating the N language entries

The anchor pool is therefore `(animals × attributes)` points in semantic space, each inheriting its parent animal's cross-linguistic phonological signature. With ~20 animals × ~10 attributes each × 16 language sound-variants, we get on the order of 3,000 anchor instances spread across hundreds of distinct semantic locations.

## Attribute bucket — Snake as example

The attributes are what makes the animal an anchor for abstract concepts, not just for sound-imitation words.

| Attribute | Concepts that might land near this anchor |
|---|---|
| close-to-ground | low, base, beneath, root, prone |
| elongated | thin, long, line, thread, narrow |
| smooth-scaled | sleek, slippery, polished |
| flexible / sinuous | bend, curve, winding, meander |
| sudden-strike | sudden, attack, ambush, quick |
| concealed | hidden, lurking, stealth, secret |
| cold-blooded | impassive, detached, calculating |
| venomous | toxic, dangerous, lethal |
| silent-movement | stealth, quiet, creep |
| cultural-cunning | clever, deceitful (Mediterranean/Christian) |
| cultural-wisdom | wise, ancient, eternal (Hindu/Buddhist) |
| cultural-fertility | renewal, rebirth (many Indigenous American) |

The cultural attributes are flagged because they're not universal. Importantly, **we don't curate these — the LLM does.** When we embed "snake" in the model's concept space, the position we get already reflects the multilingual training data's bundled understanding of what a snake is. The attribute list above is a working hypothesis for what attributes the LLM has clustered around the snake concept; the actual attribute positions come from the geometry, not from our list.

That makes the snake anchor genuinely multi-faceted in semantic space — a snake-shaped cloud of points, not a single position.

## Walkthrough — three query concepts

### "low"
- Concept embeds somewhere in semantic space.
- Nearest attribute-anchors: snake (close-to-ground), mouse (small/near-ground), worm if we include it.
- Phonological signatures: snake = /s h i/ heavy (sibilant + high vowel across languages), mouse = /i k u/ (squeak across languages, front vowels + voiceless stop).
- Interpolation: weighted toward snake, so "low" comes out with /s/+/i/ — something like /sili/ or /isin/.

### "loud"
- Nearest anchors: lion (roar), rooster (dawn call), crow (caw).
- Phonological signatures: lion = open vowels + liquids /a/ + (cross-language /r/ approximated to /l/ in our inventory), rooster = front vowels + /k/, crow = /k a/.
- Interpolation: stops + open vowels, plausibly /kala/ or /kawa/.

### "cunning"
- Nearest anchors: snake (cultural-cunning), maybe fox if we include it, maybe wolf (predator/strategy).
- Snake dominates because foxes have weak universal onomatopoeia.
- Result: /s/-heavy, sibilant phonology — semantically "hissy" word for cunning. Which is actually a *finding*: it tells us the LLM bundles cunning more with snake-schemas than with predator-schemas.

The third example is the load-bearing one. The phonology of "cunning" tells us something about how the model has organized the concept, not just what we wanted "cunning" to sound like. That's the project working as designed.

## Cross-linguistic variation is data, not noise

Some animal sounds show tight cross-linguistic agreement. Most languages render cow as /m/ + round vowel (English *moo*, Japanese *mō*, Spanish *muu*, Russian *muu*, Mandarin *mōu*, Hindi *muu*, Finnish *muu*). That gives a **sharp anchor**: the phonological signature for cow is essentially /m/ + /u/ or /m/ + /o/, with high confidence.

Other animals show wide variation. Pig is rendered very differently across languages — English *oink*, Japanese *buu-buu*, Mandarin *hāo*, Vietnamese *ụt ịt*, Russian *хрю-хрю* (*khryu*), German *grunz*. Very little phonological overlap. That gives a **fuzzy anchor**: the phonological signature for pig is more like a distribution across many feature vectors than a tight cluster.

This variation isn't a problem to fix. It's signal: some animal sounds are physically distinctive enough that human ears converge on the same imitation; others are noisy enough that cultural convention dominates. The sharpness of an anchor is itself a meaningful property — concepts near a sharp anchor get strongly iconic phonology, concepts near a fuzzy anchor get phonology with more freedom.

## Aggregation mechanics

For each animal:

1. Collect the native onomatopoeia from each of the 16 languages.
2. Get IPA transcription for each.
3. Project each IPA form onto our 10C/5V CV(n) inventory (the normalization step — Japanese *buu* → /bu/ → /pu/ since we have no /b/; the loss of voicing is part of normalization).
4. Compute mean and variance over feature vectors. The mean is the anchor; the variance tells us how sharp it is.
5. List the animal's attributes (from cultural knowledge, dictionaries, and ultimately from the LLM's actual feature clustering once Stage 4 data is in).
6. Embed each attribute in the LLM concept space.
7. Each `(animal, attribute)` pair becomes an anchor with the animal's phonological signature.

The result is a labeled point cloud in joint (semantic × phonological) space. Voronoi tessellation runs over the semantic dimensions; phonology gets pulled along.

## Open questions

- **Which 16 languages.** The starting set above is reasonable but not justified rigorously. Could pick based on (a) typological distance, (b) ideophone richness, (c) data availability, (d) speaker population. Different weightings → different sets.
- **How many animals.** ~20 seems right for a v1. Adding more increases anchor density but pulls in animals with less universal recognition (do all 16 cultures have a clear sound for "hyena"?).
- **Are attributes pre-curated or LLM-derived.** Both, probably: curated as a starting hypothesis, then validated/replaced by what the LLM clustering actually shows.
- **Non-animal anchors later.** Weather (thunder, rain, wind) and human-body sounds (laugh, sneeze, cry) could extend the anchor pool into different attribute spaces. Decide whether v1 is animals-only.
- **Verification of cross-language data.** This is the data-aggregation labor problem. Wikipedia, Wiktionary, language-specific ideophone dictionaries, and direct elicitation from native speakers all available. None complete on their own.

## How this fits the project

This anchor pool is the input to Stage 6 (phonology + site build). It's also the only stage that requires significant external data work — every other stage runs on Gemma + Neuronpedia outputs. The anchor pool can be built in parallel with Stages 1–4, since it's data-collection independent of the LLM feature extraction.
